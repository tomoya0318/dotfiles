# skill-audit rubric

読み手は **skill 1 本とこの文書だけ**を見て、逐語の証拠付きで行を返す。

## この文書の作られ方

`/audit` の rubric は判定基準を `rule:<見出し>` で正本へ指すが、**ここでは指さない。**
skill の書き方を定めた正本の文書が無いためである。指す先が無いのに指定の形だけ真似ると、
解決できない参照が増える。正本ができたら指す形に変える。

## 守ること

**判定しない。** あなたの仕事は抽出であって、良し悪しの判断ではない。
`artifact-name-drift` `duplicate-source` は主エージェントが集合として判定し、
`fork-drift` は 2 文書を渡された別の読み手が判定する。**どれも探そうとしないこと。**

**深刻度を付けない。** その skill が何から呼ばれ、どう使われているかを渡されていないため、判定できない。

**引用を捏造しない。** `quote` は本文からの逐語引用にする。
集約時に実際の行と照合され、一致しないものは捨てられる。

**構造の問題を報告しない。** 行数、frontmatter、リンク切れ、symlink は `skill-lint.py` が見る。

**散文の好みを報告しない。** 言い回し、語調、見出しの付け方、冗長さは対象外である。

**修正案を書かない。** 直すかどうかは主エージェントが決める。

**無ければ空で返す。** 無理に見つけない。

## 抽出する

1 行 1 件。同じ値が複数回出てくる場合は、最初の 1 回だけでよい。

### step

手順の見出し。番号付きの節、または「## <数字>.」の形のもの。
`value` は番号と見出しをそのまま入れる。

### produces

その skill が**生み出す**成果物のファイル名。書き出す・作成する・保存すると述べているもの。
パスの一部でも、ファイル名として言及されていれば拾う。

### references

その skill が**参照する**成果物のファイル名。読む・確かめる・行き場として挙げる、と述べているもの。
自分が `produces` として挙げたものは `references` に重ねない。

### rule

その skill が課している規律のうち、**その skill 固有の判断ではないもの**。
「〜しない」「〜に限る」「必ず〜する」の形で書かれた、他の skill でも通用しうる決めごとを拾う。

その手順の中でしか意味を持たない指示 (「pane id は手順 1 の JSON から引く」など) は拾わない。

## 観測する

### stale-reference

本文の記述が、現物と食い違っている。**この 1 つだけを見る。**

指しているパス・コマンド・ディレクトリが存在しない、
「〜が無い」と書いてあるが実在する、前提にしている状態が既に変わっている、など。
リンク切れは `skill-lint.py` が見るので報告しない。

食い違いを**確かめられた場合だけ**報告する。読んでいないファイルについて推測しない。

## 出力

1 行 1 件の JSONL で書く。

```jsonl
{"skill":"implement-approved-plan","line":90,"kind":"step","quote":"## 4. DoD を実行する","note":""}
{"skill":"land-worktree","line":94,"kind":"references","quote":"review.md","note":""}
{"skill":"land-worktree","line":150,"kind":"stale-reference","quote":"herdr worktree remove","note":"本文は使わないと述べているが手順にコマンドが残っている"}
```

| キー | 内容 |
|---|---|
| `skill` | skill の名前 |
| `line` | 1 始まりの行番号 |
| `kind` | `step` `produces` `references` `rule` `stale-reference` のいずれか。列挙値以外を使わない |
| `quote` | 本文からの逐語引用。40 字程度まで |
| `note` | `stale-reference` のときだけ、何がどう食い違うかを 1 文。他は空文字 |
